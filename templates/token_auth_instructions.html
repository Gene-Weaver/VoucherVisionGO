Method 1: Token Authentication

This method uses short-lived ID tokens (60 minutes) that are automatically refreshed while this browser page is open.

curl -X POST "{{ server_url }}/process" \
-H "Authorization: Bearer YOUR_TOKEN" \
-F "file=@your_image.jpg"

By default, Gemini calls are billed to VoucherVisionGO's shared keys and count against your per-model quota. You can instead have them billed to your own account in one of two ways. Both work from any language — they are ordinary request parameters, not something specific to the Python client.

Option A — your own Google AI Studio key

Get a key from Google AI Studio, then pass it as gemini_api_key:

curl -X POST "{{ server_url }}/process" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -F "file=@your_image.jpg" \
  -F "engines=gemini-3.1-flash-lite" \
  -F "llm_model=gemini-3.1-flash-lite" \
  -F "gemini_api_key=YOUR_GEMINI_API_KEY"

Or as a header, if your HTTP client makes that easier:

curl -X POST "{{ server_url }}/process" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "X-Gemini-API-Key: YOUR_GEMINI_API_KEY" \
  -F "file=@your_image.jpg" \
  -F "engines=gemini-3.1-flash-lite" \
  -F "llm_model=gemini-3.1-flash-lite"
Option B — your own Google Cloud project (Vertex AI)

Use this if AI Studio keys aren't available in your region, if your institution requires AI costs to land on an institutional Google Cloud account, or if you'd rather not send a long-lived key on every request. Two one-time setup steps:

  1. In your Google Cloud project, enable the Vertex AI API and grant the Vertex AI User role to vouchervision-vertex@vouchervision-387816.iam.gserviceaccount.com. We never see or store your Google Cloud credentials.
  2. Link the project ID to your VoucherVisionGO account under API Key Management → Linked Google Cloud Projects. Requests using an unlinked project ID are rejected with HTTP 403.
curl -X POST "{{ server_url }}/process" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -F "file=@your_image.jpg" \
  -F "engines=gemini-3.1-flash-lite" \
  -F "llm_model=gemini-3.1-flash-lite" \
  -F "vertex_project=your-gcp-project-id" \
  -F "vertex_region=global"

Header form:

curl -X POST "{{ server_url }}/process" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -H "X-Vertex-Project: your-gcp-project-id" \
  -H "X-Vertex-Region: global" \
  -F "file=@your_image.jpg" \
  -F "engines=gemini-3.1-flash-lite" \
  -F "llm_model=gemini-3.1-flash-lite"

Use vertex_region=global unless you have a specific reason not to — regional endpoints do not carry every model.

Confirming which account was billed

Every response carries an X-VV-Billing-Mode header whose value is user_gemini, user_vertex, or server. Check it to confirm your credentials were actually picked up.

If you supply a credential the server can't read — a misspelled parameter name, or an empty value — the request is rejected with HTTP 400 rather than quietly falling back to VoucherVisionGO's shared keys. A credential that is read but invalid or over quota surfaces the error from Google; it is never retried on our keys.

Note: /process-pdf-async does not yet accept gemini_api_key. Use Vertex AI (Option B) for async PDF jobs.

// Token Authentication Example
import { initializeApp } from "firebase/app";
import { getAuth, signInWithEmailAndPassword } from "firebase/auth";

// Initialize Firebase
const firebaseConfig = {
  apiKey: "YOUR_API_KEY",
  authDomain: "YOUR_AUTH_DOMAIN",
  projectId: "YOUR_PROJECT_ID"
};

const app = initializeApp(firebaseConfig);
const auth = getAuth(app);

// Sign in and get token
async function getToken() {
  try {
    const userCredential = await signInWithEmailAndPassword(auth, "email@example.com", "password");
    const idToken = await userCredential.user.getIdToken();
    return idToken;
  } catch (error) {
    console.error("Authentication error:", error);
    return null;
  }
}

// Use token to call API
async function processImage(imageFile) {
  const token = await getToken();
  if (!token) return null;
  
  const formData = new FormData();
  formData.append('file', imageFile);
  
  const response = await fetch('{{ server_url }}/process', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${token}`
    },
    body: formData
  });
  
  return await response.json();
}
  • Token lifetime: 60 minutes

  • Best for: Interactive applications, development, testing
  • Security level: High - tokens are short-lived and tied to your Firebase account

For automated or scheduled tasks where user interaction is not possible, consider using API Key authentication instead.
